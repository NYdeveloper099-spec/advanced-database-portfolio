# Portfolio 4: NoSQL and Advanced Data Models

## 1. Case Study

This portfolio continues the University Student Result Management System developed in the previous portfolios. The system manages student information, departments, courses, registrations, lecturers, and academic results.

## 2. Aim

The aim of this portfolio is to explore how a NoSQL database can represent and query student academic information, and to compare the NoSQL approach with the relational database design used in the earlier portfolios.

## 3. Objectives

- Explain the purpose and characteristics of NoSQL databases.
- Design a document-based data model for the university system.
- Insert and query sample student and academic records.
- Examine how document embedding and referencing affect data organisation.
- Compare the document model with the existing relational model.
- Record practical results, screenshots, and technical observations.

## 4. Planned Tools

- MongoDB and MongoDB Query Language (MQL), subject to environment availability.
- A browser-based or locally available MongoDB environment.
- GitHub for version control and documentation.

## 5. Planned Activities

1. Create a document model for student academic records.
2. Insert representative sample documents.
3. Run queries to retrieve and filter student and result information.
4. Explore document embedding or referencing.
5. Compare the NoSQL model with the relational schema.
6. Save scripts, query results, screenshots, and analysis.

## 6. Evidence

Practical evidence, scripts, and the completed analysis will be added as the activities are performed. Findings will be documented based on observed results.

## 7. Case Study Continuity

The University Student Result Management System remains the case study for this portfolio and the overall Advanced Database Systems project.
